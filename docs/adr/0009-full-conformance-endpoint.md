# ADR 0009：完整符合性终点——以 Excel 2024 / 2610 公式语言为目标标准

- 状态：已接受（2026-11-21）
- 取代：ADR 0003（窄而深子集）、ADR 0006（约 50 函数子集）、ADR 0007（60 函数子集）
- 修订：ADR 0008 的“完整 Excel 不作承诺”终点表述；ADR 0008 的引用语义实现仍有效

## 背景

2026 MoonBit 开源大赛十一月黑客松初审指出：MoonCalc 已具备离线表格计算价值，MoonBit 求值与增量计算也有实质工作，但申报把“自定义公式子集”当作最终验收终点，并明确排除交集、数组公式等标准语义；这不满足“公式语言实现的完整兼容终点”要求。

根因不是工程能力，而是**终点声明**：旧文档把“当前已覆盖的函数/引用子集”写成验收边界，把未实现语义移出分母。ADR 0003/0006/0007 的“窄而深”是有效的阶段策略，但不能作为最终标准；ADR 0008 的 L1/L2/L3 是里程碑，不是终点。

## 决定

### 1. 目标标准及版本

目标标准是**桌面 Excel 2024（版本 2610，Build 16.0.20527.20196，zh-CN）的公式语言与计算语义**，具体包括：

- 公式语法：A1 引用（相对/绝对/混合）、区域、整列/整行、跨表引用、3D 引用、外部工作簿引用、定义名称（工作簿级与工作表级）、数组字面量、`:` 区域运算符、空格交集运算符、逗号并集运算符、`@` 隐式交集运算符、`#` 溢出运算符、一元/二元运算符与优先级、函数调用与空实参；
- 引用与值语义：引用通道与数组通道、隐式交集、显式交集、并集、逐元素数组运算与标量广播、CSE 多格公式、动态数组溢出与 `#SPILL!`、错误值（含 `#NULL!`、`#SPILL!`、`#CALC!`）、空白/文本型数字/布尔的强制转换；
- 函数语义：目标版本公式语言中的**全部内置函数**，不设“60 函数”上限；
- 计算模式：默认循环引用语义、可选迭代计算、日期系统（1900/1904）、时钟函数、易失函数；
- 工作簿级引用：跨表、名称、3D、外部链接。

**版本钉死**：答案键与验收以 2610 / 16.0.20527.20196 为准；后续 Excel 版本的行为变化另立 ADR 与语料批，不静默混入。

### 2. 完整符合性承诺

MoonCalc 的最终验收终点是：**对上述目标标准中的公式语言与计算语义逐项符合**；不再把任何标准语义（包括交集、并集、隐式交集、CSE、动态数组、`#SPILL!`）声明为“不在验收范围”。

“完整符合性”指公式语言与计算语义，不包括与公式计算无关的产品能力：图表、VBA/宏、条件格式/样式、数据透视表、UI/文件格式细节。这些非公式能力明确不在本终点内；它们不影响“公式语言完整兼容”的判定。

### 3. 当前覆盖与缺口（不夸大）

### 4. 分阶段里程碑

| 里程碑 | 范围 | 完成判据 |
| --- | --- | --- |
| M9（已完成，2026-11-21 时点） | 数组字面量、交集/并集/`@`、隐式交集、CSE、动态 spill、`#SPILL!`、`#NULL!`、`PRODUCT` | 238 条新答案键全过；时点全量 1,505/1,505；数组 demo 35/35 |
| M9.1（已完成，2026-11-21） | `D4#` 引用通道与隐式交集、spill 锚点错误传播、CSE→动态依赖预求值 | 23 条新答案键全过；全量 1,528/1,528；数组 demo 39/39 |
| M10 | 函数广度：按目标版本函数目录逐族补齐全部内置函数 | 每个函数 ≥15 条真实 Excel 答案键；函数级矩阵无“未实现” |
| M11 | 引用完整性：3D 引用、外部工作簿链接、工作表级名称、空实参、R1C1（若目标版本公式语言要求） | 每项有答案键；解析/求值/增量/explain 同步 |
| M12 | 动态数组函数族：FILTER/SORT/SORTBY/UNIQUE/SEQUENCE/RANDARRAY 等，及其与 CSE/`#`/spill 的交互 | 函数级答案键 + spill 阻塞/引用案例 |
| M13 | 计算模式与边界：1904 日期系统、locale 相关解析/格式、迭代/易失函数的完整交互 | 真实 Excel 答案键；文档披露所有剩余差异 |
| M14 | 全量复核 | 目标标准公式语言无未实现项；所有缺口关闭或书面降级；语料通过率 100% |

里程碑可以并行/调整顺序，但**不得把未完成项从验收分母移出**；未通过项必须作为公开缺口列出。

### 5. 证据与可复现性

- 每批答案键由真实桌面 Excel（2610 / 16.0.20527.20196）生成，带版本指纹、生成脚本、SHA-256 与排除理由（`corpus/cases/PROVENANCE.md`）。
- 探针先行：未知语义先在真实 Excel 上跑探针，语义以探针结果为准；探针与答案键分离（`corpus/probes/`）。
- 通过率只来自实跑；不得手写期望值，不得把失败用例悄悄移出分母。
- 对比报告（mbtexcel 等）标注其覆盖的语料版本，不把旧分母数字冒充新分母。

## 后果

- 文档中“不承诺完整 Excel”“排除在验收分母之外”“子集外行为显式约定”等终点口径全部改为“当前覆盖 / 当前缺口 / 里程碑”。
- `docs/semantics.md`、`README.md`、`docs/support-matrix.md`、`docs/conformance-kit.md`、`docs/comparison-mbtexcel.md` 同步改写；历史 ADR 保留，仅标注 Superseded。
- 函数子集不再是“最终契约”，而是当前覆盖快照；新增函数不需要先改终点声明。
- 工程上保留 `recalc` 的向后兼容；数组/CSE 通过 `ArrayLayout` 侧契约进入，不破坏旧网格 API。
