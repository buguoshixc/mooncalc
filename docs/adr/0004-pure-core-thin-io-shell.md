# 纯计算核心 + 薄 IO 壳，引擎支持全后端

引擎核心不做任何 IO，因此可同时编译到 native 与 wasm-gc：native 侧提供 CLI 用于答案键语料对照跑分，wasm-gc 侧提供浏览器 playground 用于现场演示。文件读写、Excel 语料生成等 IO 全部留在核心之外的薄壳里。

## 备选方案

- 只做 native CLI：范围最小、16 天最稳，但演示只有终端输出与报告表格，视觉冲击弱。
- native CLI + 静态 HTML 报告：成本低于 playground，但没有「现场算给你看」的效果。

## 后果

「核心无 IO」成为硬性架构约束：一旦 IO 渗入核心，wasm 后端即失效，playground 随之报废。因此核心的输入输出只能是内存中的网格契约，任何文件访问都必须发生在壳层。
